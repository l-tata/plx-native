## Known issues at release, with provenance

- **Mid-stream frame-rate change on a Tunarr channel.** Known from the design (`docs/live-tv-plan.md`, risk 2): the frame rate is probed once at tune and declared at Load; nothing re-Loads on a change. Not measured. Tunarr's frame-rate normalisation avoids it.
- **Guide times and the television's time zone.** `docs/agent-reference.md` records the dev set's pmlog wall clock as about three hours off, which suggests the zone is not visible to a native process. `plx_base::wallclock` falls back to the zone Tunarr writes XMLTV in while the C library reports UTC. Not measured on a television.
- **No On Now row.** Not built (`docs/live-tv-plan.md`, status).
- **The clock's zone.** `plx_base::wallclock` uses `localtime`, then the set's `luna://com.palm.systemservice/time/getSystemTime` offset (asked once at boot, parsed by `plx_platform::webos::parse_system_time_offset` from the reply shape the webOS TV reference documents), then the Tunarr guide's zone. Whether a jailed native process sees its zone through `localtime`, and whether that service answers it, has not been observed on a television.

## Deliberately not done

- The replay fixtures under `tests/fixtures/replay/` were not re-recorded. Adding the Live TV screen moved the screen shape pin (`SCREEN_SHAPES_PIN`), so the macOS simulator's replay gate refuses them until `tools/plxnative-rec rerecord` is run on a Mac.
- No `make build-bench` table: `rust-modules/data/Cargo.toml` gained a path dependency on `plx_net`, and the tool was not run.
- The documentation screenshots were not regenerated, so the README's and the website's stills do not show the Live TV tab, the Settings → Live TV row or the Go to Show button.
- The webosbrew listing and the `webosbrew/apps-repo` submission belong to the upstream project and were not touched.

## Release configuration

| | |
|---|---|
| flavour | `com.beb.plxnative` (stable) — the id users install; `FLAVOR: stable` is pinned in the release workflow's build job |
| cargo features | `RELEASE=1`, which drops `devtools` and `devtriggers` |
| built by | GitHub Actions, from the tag, at a path identical on every runner |
| toolchain | webOS NDK unchanged, Rust nightly pinned by date in the `RUST_NIGHTLY` repository variable |

New platform calls: `luna://com.palm.systemservice/time/getSystemTime` once at boot, inside the same 600 ms budget as the locale query. New outbound traffic: the app sends an SSDP M-SEARCH to the multicast group 239.255.255.250:1900 on the local network when Settings → Live TV searches, and plain HTTP requests to the configured Tunarr origin (`/discover.json`, `/lineup.json`, `/api/xmltv.xml`, `/stream/channels/*.ts`). Two new values are written to the session file: the Tunarr origin and the last channel tuned. No new payload file, no new file written outside the app's own directory, and no toolchain or third-party dependency change. The fork's repository has no production telemetry variables, so this build compiles in no telemetry endpoint.
