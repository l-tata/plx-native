The evidence behind [the v0.12.0 release note](https://github.com/l-tata/plx-native/blob/main/docs/release-notes/v0.12.0.md). Written for a webosbrew reviewer, a contributor auditing an old release, and us in a year. This release is cut from the fork `l-tata/plx-native`, not from `GLinnik21/plx-native`.

## Compatibility tiers, and what moved

Nothing moved. No television ran this version, so no playback line is claimed, and the startup tier rests on the generated firmware check below. No FFI, linkage, Starfish, ACB, curl or FFmpeg binding changed since v0.11.0.

## Known issues at release, with provenance

- **A kept channel is a visible Plex playlist.** By design (the channel must reach every television in the house without a server of our own); its title starts with a TV mark and its summary carries the channel's recipe as JSON.
- **A channel draws from at most 4,000 programmes.** A bound in the catalog (`data/src/vchannel/catalog.rs`) chosen to keep building a schedule quick on the television; not measured on one.
- **Virtual channel playback, pause-behind-live and the Live TV audio buffering** are exercised only by host tests and the simulator, never by the television's player.
- **Playlist writes** (`POST /playlists`, `PUT /playlists/{id}`, `PUT`/`DELETE /playlists/{id}/items`, `DELETE /playlists/{id}`) and `GET /identity` are implemented from `docs/plex-openapi.json` and exercised only against the mock PMS.

## Deliberately not done

- The replay fixtures and documentation screenshots were not regenerated (as for v0.9.0 to v0.11.0).
- Channels are only suggested, never created on their own, and there is no cap on how many a household keeps.
- Watching a virtual channel writes nothing to the viewing record: no timeline, no scrobble, no PlayQueue.
- The webosbrew listing and the `webosbrew/apps-repo` submission belong to the upstream project and were not touched.

## Release configuration

| | |
|---|---|
| flavour | `com.beb.plxnative` (stable) — the id users install; `FLAVOR: stable` is pinned in the release workflow's build job |
| cargo features | `RELEASE=1`, which drops `devtools` and `devtriggers` |
| built by | GitHub Actions, from the tag, at a path identical on every runner |
| toolchain | webOS NDK unchanged, Rust nightly pinned by date in the `RUST_NIGHTLY` repository variable |

New outbound traffic since v0.11.0: writes to the profile's own Plex server, and only when a person keeps, edits or deletes a channel — creating, renaming and deleting a playlist and replacing its items — plus `GET /identity` on that server to name it in a playlist's item URI; reads of library sections, their items and their filter values to build suggestions and schedules. Nothing new to plex.tv or any other host. New file: `<id>-vchannel-dismissed.json` (per profile, the suggestion ids marked Not Interested, at most 400 each), beside the session and removed by Delete all data. No new payload file, and no toolchain or third-party dependency change. The fork's repository has no production telemetry variables, so this build compiles in no telemetry endpoint.
